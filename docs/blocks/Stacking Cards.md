# Stacking Cards Block

**Status:** Proposed, pending approval.
**Target block:** `nextora/stacking-cards`
**For:** Nextora theme block implementation
**Reference pattern:** `blocks/text-list-hover-image/` for the repeater item editor, item modal, media picker, and reorder controls.

## 1. Overview

Create a vertically scrolling card stack. Each card contains text on the left and an image on the right. During page scroll:

- The first card reaches a calculated position in the middle of the viewport and remains sticky there.
- The next card continues upward and overlaps the previous card with a configurable vertical offset, defaulting to `24px`.
- Every later card uses the same offset and a higher stacking order, producing a progressive stack.
- Cards return to normal document flow when their containing block ends.

The front-end interaction must use CSS only. No front-end JavaScript, GSAP, IntersectionObserver, scroll listener, CSS scroll-driven animation, or third-party dependency is required.

The block is a dynamic block with an item repeater. The editor uses React only for authoring and previewing the saved attributes.

## 2. CSS Feasibility And Constraints

The effect is implemented with `position: sticky` rather than `position: fixed`:

```css
.card {
  position: sticky;
  top: calc(50vh - (var(--nextora-sc-card-height) / 2) + var(--nextora-sc-stack-offset));
}
```

The card height must be explicit or bounded so the first card can be vertically centered reliably. Each item receives an inline CSS custom property containing its stack index. Its sticky top offset is calculated from that index and the global overlap offset.

Important implementation constraints:

- Do not place `overflow: hidden`, `overflow: auto`, `overflow: scroll`, or `contain` values that create a scrolling ancestor on the block or its card list unless the behavior is intentionally changed to an inner scroll container.
- The list must have enough vertical height for each sticky card to reach and hold its threshold. Cards remain in normal flow and therefore naturally provide the scroll height.
- The last card may stop before the visual viewport center when the section reaches its bottom boundary. This is standard sticky behavior, not a JavaScript defect.
- If the configured card height is taller than the available viewport, the centered top calculation is clamped to the configured mobile/desktop safe inset.
- Stacking order must be deterministic: item index `0` has the lowest `z-index`, and later items appear above earlier items.

This approach is supported by current modern browsers. The implementation must include a normal-flow fallback: cards remain readable as ordinary block cards when sticky positioning is unavailable.

## 5. Attributes

### 5.1 Cards repeater

Attribute: `cards`, type `array`.

Default: four cards with empty images and useful placeholder copy. The item shape is:

| Field | Type | Default | Editor control |
|---|---|---|---|
| `id` | `string` | auto-generated | Not editable |
| `heading` | `string` | `New card` | TextControl |
| `description` | `string` | `"Add a short description."` | TextareaControl |
| `linkText` | `string` | `Read more` | TextControl |
| `linkUrl` | `string` | `""` | TextControl, URL placeholder |
| `imageId` | `number` | `0` | MediaUpload |
| `imageUrl` | `string` | `""` | Stored from MediaUpload |
| `imageAlt` | `string` | `""` | TextControl |

The link is optional. When `linkUrl` is empty, render the link content as a non-interactive span or omit it according to the `showLink` setting. Do not output an empty anchor.

### 5.2 Layout settings

| Attribute | Type | Default | Control | Range / options |
|---|---|---:|---|---|
| `cardHeight` | `number` | `520` | RangeControl | `280`–`760`, step `10` px |
| `cardGap` | `number` | `32` | RangeControl | `0`–`120`, step `4` px |
| `stackOffset` | `number` | `24` | RangeControl | `0`–`80`, step `4` px |
| `cardRadius` | `number` | `20` | RangeControl | `0`–`40`, step `2` px |
| `contentPadding` | `number` | `48` | RangeControl | `16`–`96`, step `4` px |
| `imageWidth` | `number` | `50` | RangeControl | `30`–`70`, step `5` percent |
| `contentMaxWidth` | `string` | `"1200px"` | TextControl | CSS length |
| `mobileCardHeight` | `number` | `460` | RangeControl | `240`–`700`, step `10` px |
| `mobileContentPadding` | `number` | `24` | RangeControl | `12`–`56`, step `4` px |
| `mobileImageHeight` | `number` | `240` | RangeControl | `140`–`420`, step `10` px |
| `mobileStackOffset` | `number` | `16` | RangeControl | `0`–`48`, step `4` px |

`imageWidth` is the desktop image column percentage. The content column occupies the remaining width. On narrow screens the card switches to a vertical layout and uses `mobileImageHeight`.

### 5.3 Typography settings

### 5.4 Display and interaction settings

| Attribute | Type | Default | Control |
|---|---|---:|---|
| `showLink` | `boolean` | `true` | ToggleControl |
| `openLinksInNewTab` | `boolean` | `false` | ToggleControl |
| `imagePosition` | `string` | `"right"` | SelectControl: `right`, `left` |

When `enableSticky` is false, the same markup renders as normal-flow cards and the CSS sticky rules are disabled. This is useful for short sections, reduced-motion preferences, or layouts where stacking is not desired.

## 6. Editor Requirements

### 6.1 Inspector panels

Follow the `text-list-hover-image` panel pattern:

| Panel | Controls |
|---|---|
| **Cards** (initially open) | Repeater rows with thumbnail, heading preview, Edit button, move up, move down, remove; bottom Add card button |
| **Layout** | All desktop/mobile dimensions, gap, stack offsets, radius, image width, content max width |
| **Typography** | Heading/description/link sizes, weight, text alignment |
| **Display** | Show link, open new tab, image position, object fit, enable sticky |
| **Colors** | PanelColorSettings for all five color attributes |

Do not allow removing the final card. New cards receive a unique id and a default heading.

### 6.2 Edit card modal

Use a two-column `Modal` matching the existing text-list-hover-image UI:

- Left column: image preview, Choose/Replace/Remove image, image alt text.
- Right column: heading, description, link text, link URL, open-in-new-tab is global and therefore not duplicated here.
- Footer: Save and Cancel.
- Modal title: `Edit card`.
- All labels and help text use the `nextora` text domain.

### 6.3 Editor preview

Render a faithful static preview using the same card markup and CSS variables, but do not force the editor canvas to scroll or sticky-position cards. The preview should show:

- Text on the configured side and image on the opposite side.
- Placeholder image when no media is selected.
- Heading, description, and link preview.
- Card order and approximate dimensions.

The editor must remain usable when selecting, editing, and reordering cards.

## 7. Front-End Markup

`render.php` must use `get_block_wrapper_attributes()` and sanitize all attributes. Suggested structure:

```html
<section class="wp-block-nextora-stacking-cards">
  <div class="nextora-stacking-cards__list">
    <article
      class="nextora-stacking-cards__card"
      style="--nextora-sc-index: 0"
    >
      <div class="nextora-stacking-cards__content">
        <h2 class="nextora-stacking-cards__heading">Heading</h2>
        <p class="nextora-stacking-cards__description">Description</p>
        <a class="nextora-stacking-cards__link" href="/example">Read more</a>
      </div>
      <div class="nextora-stacking-cards__media">
        <img class="nextora-stacking-cards__image" src="..." alt="..." loading="lazy" />
      </div>
    </article>
  </div>
</section>
```

Requirements:

- Use semantic `article`, heading, paragraph, and anchor elements.
- Use `wp_get_attachment_image()` when `imageId` is available, falling back to the stored URL.
- The first image may use normal loading; later images should use `loading="lazy"`.
- Never render an image with an empty `src`.
- Escape URLs, attributes, and text appropriately. Descriptions may use plain text only unless the implementation explicitly adds a controlled KSES allowlist.
- Add `target="_blank"` and `rel="noopener noreferrer"` only when `openLinksInNewTab` is enabled.
- Set item index, all layout values, and resolved colors through scoped CSS custom properties on the wrapper/card.
- Add a class indicating sticky is enabled so CSS can disable it cleanly.

## 8. CSS Behavior

### Desktop

- The list is a vertical flow layout with `gap: var(--nextora-sc-card-gap)`.
- Each card has `min-height`/`height` driven by `cardHeight`, `display: grid`, and two columns.
- Text and image columns are controlled by `imageWidth` and `imagePosition`.
- Sticky top is calculated from viewport height, card height, and item index:

```css
.nextora-stacking-cards__card {
  position: sticky;
  top: max(
    24px,
    calc(
      50vh - (var(--nextora-sc-card-height) / 2) +
      (var(--nextora-sc-index) * var(--nextora-sc-stack-offset))
    )
  );
  z-index: calc(10 + var(--nextora-sc-index));
}
```

- Card backgrounds must be opaque so underlying cards are visually covered.
- Use `overflow: clip` or `hidden` only on the card itself, never on the sticky list ancestor.
- Use transforms only for optional subtle visual treatment; do not transform the sticky card or its ancestors in a way that changes sticky behavior.
- The overlapping area must not hide the content needed to understand the active card. The default card design should keep the upper `stackOffset` band visually calm, with the main content padded below it.

### Mobile

- At the mobile breakpoint, cards use a single column with the image above or below the content according to `imagePosition`.
- Sticky remains enabled by default, but uses `mobileCardHeight` and `mobileStackOffset`.
- At very narrow widths, cards may use normal flow if the configured content cannot fit without clipping. This must be done with a media query, not JavaScript.
- Links remain keyboard and touch accessible with a minimum comfortable hit area.

### Reduced motion and fallback

The layout itself is not an animation, but the stack can be visually intense. Under `prefers-reduced-motion: reduce`:

- Remove transitions and decorative transforms.
- Keep sticky behavior because it is layout, not motion, unless the implementation determines that a normal-flow fallback is more accessible.
- Ensure all card content remains visible and in DOM order.

When `enableSticky` is false, set `position: relative` or `static`, reset `top`, and reset `z-index` so cards become normal-flow cards without overlap.

## 9. Accessibility

- Preserve DOM order: heading, description, link, then image or a consistent visual order that does not change reading order unexpectedly.
- Use a heading level appropriate for a section, configurable only if the theme block conventions require it; do not hardcode an invalid heading hierarchy without checking the surrounding content.
- Image alt text is editable per card. Decorative images may use an empty alt value.
- Links must have meaningful visible text and a visible `:focus-visible` style.
- Do not rely on z-index or visual overlap to communicate content order.
- Test keyboard navigation while cards overlap and at 200% zoom.
- Test with reduced motion, touch input, and screen readers.

## 10. Validation Checklist

Before implementation is considered complete:

- Add/register the block through the normal `blocks/blocks.php` glob/build path.
- Run `npm run build`.
- Run `npm run typecheck`.
- Run `npm run lint:php:all`.
- Verify desktop scroll behavior with 2, 4, and 8 cards.
- Verify the first card centers correctly at multiple viewport heights.
- Verify the last card exits at the section boundary.
- Verify behavior when an ancestor has `overflow: hidden` and document the limitation rather than adding JavaScript compensation.
- Verify mobile layout, touch links, missing images, long headings, long descriptions, and no-link cards.
- Verify editor modal save/cancel, media replacement/removal, reorder, delete protection, and all inspector settings.

## 11. Explicit Non-Goals

- No scroll event JavaScript.
- No GSAP or `viewScript`.
- No hover-only content or hover-only links.
- No modal/lightbox for card images.
- No dynamic measurement of card height in JavaScript.
- No dependency on Tailwind, shadcn, or `lucide-react` for the front-end block.
