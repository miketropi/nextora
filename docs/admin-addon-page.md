# Nextora Addon — Admin Page

WordPress admin page under **Nextora Addon** that showcases child themes, supported plugins/extensions, and business services in a React-powered UI using `@wordpress/components`.

## Menu

- **Page title**: Nextora Addon
- **Menu title**: Nextora Addon
- **Capability**: `manage_options`
- **Slug**: `nextora-addon`
- **Icon**: `dashicons-admin-generic`
- **Position**: 30

Registered via `admin_menu` hook in `extensions/admin-menu.php`. The page callback prints a root `<div id="nextora-addon-root">` where React mounts.

## Tabs

Three tabs powered by `TabPanel` (`@wordpress/components`):

1. **Child Themes** — available child themes for Nextora
2. **Extensions** — supported plugins/extensions
3. **Business Services** — services offered by the business/developer

Each tab fetches its data from a dedicated REST endpoint on mount.

## Data layer

### Source: Hardcoded PHP arrays (extensible via filters)

All data is defined as static arrays in PHP under `extensions/data/`. Child themes and plugins can self-register via WordPress filters.

### Data shape

**Child Theme** (`nextora_addon_child_themes` filter):

```ts
{
  slug: string;
  name: string;
  description: string;
  thumbnail: string;
  url: string;
  author: string;
}
```

**Plugin** (`nextora_addon_plugins` filter):

```ts
{
  slug: string;
  name: string;
  description: string;
  icon: string;
  url: string;
  isActive: boolean; // detected at runtime via REST endpoint
}
```

**Business Service** (`nextora_addon_business_services` filter):

```ts
{
  id: string;
  title: string;
  description: string;
  icon: string;      // dashicon slug or SVG URL
  url: string;
}
```

### REST API

All endpoints are registered under the `nextora/v1` namespace with `manage_options` capability check and nonce verification.

| Method | Route | Returns |
|--------|-------|---------|
| `GET` | `/nextora/v1/addon/child-themes` | `ChildTheme[]` |
| `GET` | `/nextora/v1/addon/plugins` | `Plugin[]` (with live `isActive` detection) |
| `GET` | `/nextora/v1/addon/business-services` | `BusinessService[]` |

## React app

### Entry (`resources/ts/admin-addon/index.tsx`)

Renders `<App />` into `#nextora-addon-root` using `createRoot` / `render` from `@wordpress/element`.

### Components

```
resources/ts/admin-addon/
├── index.tsx                  # Entry — renders App into DOM
├── App.tsx                    # TabPanel wrapper, tab routing
├── components/
│   ├── Header.tsx             # Page title + description banner
│   ├── CardGrid.tsx           # Responsive CSS grid of cards
│   ├── ExtensionCard.tsx      # Icon, title, description, status, action button
│   ├── ChildThemesTab.tsx     # Fetches + renders child theme cards
│   ├── PluginsTab.tsx         # Fetches + renders plugin cards with active/inactive badge
│   └── BusinessServicesTab.tsx# Fetches + renders business service cards
├── hooks/
│   └── useAddonData.ts        # Generic fetch hook calling apiFetch
└── types.ts                   # TypeScript interfaces
```

### Data fetching

Uses `@wordpress/api-fetch` for REST calls. The hook `useAddonData<T>(endpoint)` handles loading, error, and data states. REST URL and nonce are localized via `wp_localize_script`:

```php
wp_localize_script('nextora-admin-addon', 'nextoraAddon', [
    'restUrl' => esc_url_raw(rest_url('nextora/v1/addon')),
    'nonce'   => wp_create_nonce('wp_rest'),
]);
```

### Card design

Each card follows a consistent layout:
- **Icon** (left or top) — dashicon class or image
- **Title** (16px, semibold)
- **Description** (13px, secondary color)
- **Status badge** (plugins only — active/inactive pill)
- **Action button** (outlined/secondary, links to external URL or WP plugin install)

Cards render in a responsive grid:
- 3 columns on wide screens (>1200px)
- 2 columns on medium (~782–1200px)
- 1 column on small (<782px)

## PHP files

### `extensions/` (theme root)

```
extensions/
├── load.php                    # Entry point — required from functions.php
├── admin-menu.php              # add_menu_page + page render callback
├── admin-enqueue.php           # Enqueue JS/CSS on the addon page
├── rest-routes.php             # Register REST API routes
└── data/
    ├── child-themes.php        # nextora_get_child_themes()
    ├── plugins.php             # nextora_get_supported_plugins()
    └── business-services.php   # nextora_get_business_services()
```

### Entry in `functions.php`

Added after the last existing `require_once`:

```php
require_once NEXTORA_DIR . '/extensions/load.php';
```

### Admin enqueue

Only loads on the addon page (hook `toplevel_page_nextora-addon`). Reads dependencies from `assets/js/admin-addon.asset.php` (generated by esbuild). Enqueues:

- `nextora-admin-addon` (JS handle) — React app
- `nextora-admin-addon-style` (CSS handle) — admin styles

## Build pipeline

### `scripts/build-admin-addon.mjs`

New esbuild script following the same pattern as `scripts/build-editor.mjs`:

- **Entry**: `resources/ts/admin-addon/index.tsx`
- **Output**: `assets/js/admin-addon.js`
- **Asset file**: `assets/js/admin-addon.asset.php` (dependencies + version)
- **Format**: IIFE, es2020, minified
- **JSX**: automatic, `react-jsx`
- **Externals**: `@wordpress/*` → `window.wp.*`, `react` → `window.React`, `react-dom` → `window.ReactDOM`
- **Watch mode**: `--watch` flag

### CSS

`resources/css/admin-addon.css` is plain CSS (no Tailwind dependency needed for admin). Compiled via PostCSS or copied as-is to `assets/css/admin-addon.css`.

### npm scripts (added to `package.json`)

```json
"build:admin-addon": "node ./scripts/build-admin-addon.mjs",
"build:admin-css": "postcss ./resources/css/admin-addon.css -o ./assets/css/admin-addon.css",
"watch:admin-addon": "node ./scripts/build-admin-addon.mjs --watch"
```

The `build:admin-addon` and `build:admin-css` are added to the main `build` script. Watch counterparts are added to `watch`.

### tsconfig.json

```json
"include": [
  "resources/ts/**/*.ts",
  "resources/ts/**/*.d.ts",
  "resources/ts/**/*.tsx",
  "blocks/**/*.ts",
  "blocks/**/*.tsx",
  "blocks/**/*.d.ts"
]
```

(`resources/ts/**/*.tsx` is already covered by `resources/ts/**/*.ts` — but explicitly listing it doesn't hurt.)

## Default seed data

### Child themes

An empty array by default. Child themes register themselves via the `nextora_addon_child_themes` filter:

```php
add_filter('nextora_addon_child_themes', function(array $themes): array {
    $themes[] = [
        'slug'        => 'nextora-child',
        'name'        => 'Nextora Child',
        'description' => 'A starter child theme for Nextora.',
        'thumbnail'   => 'https://example.com/thumbnail.png',
        'url'         => 'https://example.com/nextora-child',
        'author'      => 'Your Name',
    ];
    return $themes;
});
```

### Plugins

Pre-seeded with common plugins the theme explicitly supports (WooCommerce, Elementor, GiftFlow, etc.):

```php
[
    'slug'        => 'woocommerce',
    'name'        => 'WooCommerce',
    'description' => 'Sell anything — the most customizable eCommerce platform.',
    'icon'        => 'dashicons-cart',
    'url'         => 'https://woocommerce.com',
]
```

`isActive` is computed live in the REST response via `is_plugin_active()`.

### Business Services

Static list seeded with example entries:

```php
[
    'id'          => 'custom-dev',
    'title'       => 'Custom WordPress Development',
    'description' => 'Bespoke themes, plugins, and block development.',
    'icon'        => 'dashicons-admin-customizer',
    'url'         => 'https://example.com/services/custom-dev',
]
```
